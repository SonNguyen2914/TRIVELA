## 2. Findings

### A1 — Club resolution can silently attach data on a name match

**Severity:** HIGH · **Class:** `ACTIVE_TRIVELA_ASSUMPTION`
**File:** `src/live/identity.py:184-189`

```python
if name:
    for t in s.query(Team).filter_by(competition_slug="mls-2026"):
        cn = norm(t.canonical_name)
        if norm(name) == cn or norm(name) in cn or cn in norm(name):
            return t
```

Returns the **first** containment match with no ambiguity check,
contradicting `AGENTS.md` §6 (*"an ambiguous identity match must fail
explicitly, never silently pick a team"*) and §13's provider-stable-ID
requirement.

Dormant today — the `abbrev == code` path is a verified 30/30 1:1 — but
its stated purpose is defence against expansion drift, i.e. it is built
to activate exactly when name collisions become likely. MLS first teams
have NEXT Pro reserve sides whose names are supersets of the parent
(*Columbus Crew 2*, *Austin FC II*). The `cn in norm(name)` arm attaches
those to the first team: not a crash, but reserve stats folded into
first-team xG ratings and every lock downstream.

**Correction — revised.** The first revision recommended "collect all
containment matches, accept exactly one." **That fix does not work**, and
the review was right to reject it:

- with only *Columbus Crew* seeded, *Columbus Crew 2* still yields
  exactly one containment match and still attaches — the very case the
  finding is about
- with both seeded, an exact *Columbus Crew 2* input yields two matches
  and the rule would reject a **valid exact identity**

Correct approach: **final attachment must require the stable provider
code or an approved alias.** An unknown code returns `None` and emits an
observable unmapped-identity result. Containment may at most *propose* an
alias for curation; it must never attach data.

**Minimum acceptance test.** With only the parent club seeded, resolve
with an unknown code and name `"Columbus Crew 2"`; assert `None` **and**
an emitted unmapped-identity record. Separately assert an exact seeded
name with a known code still resolves. Confirm the first fails against
the current implementation.

### A2 — Multi-league abstraction is schema-only

**Severity:** HIGH · **Class:** `ACTIVE_TRIVELA_ASSUMPTION`
**File:** `src/live/models.py:45-46`, `src/live/db.py:115-116`,
`src/live/model_mls.py:509,533`

**Revision 1 certified this as sound. That was wrong**, and it was the
most damaging error in the document: it appeared under "verified
sound — do not re-report", which would have instructed future reviewers
to skip a real modelling-safeguard issue.

`Competition.has_group_stage` / `has_knockout_stage` exist in the schema,
the migration and the seed — and have **zero runtime consumers**. Nothing
reads them to select semantics. Meanwhile:

- `model_mls.py:509` and `:533` both hardcode `stage="group"`
- `competition_slug="mls-2026"` is hardcoded 30 times across `src/live/`

So the correct description is **generic schema, MLS-specific
implementation**. MLS playoff fixtures would not automatically take
knockout semantics, and another league cannot traverse the current flow
by adding data alone.

**Recommended correction.** State the limitation honestly rather than
implying abstraction. If runtime abstraction is intended, it needs
fixture-level competition phase and competition context — not a
competition-wide playoff flag that no code reads.

## 3. Verified sound — do not re-report

Re-checked after review. These stand.

**Temporal leakage: clean.** `model_mls.fit(fixtures, as_of)` takes an
explicit cutoff; `_completed(s, before)` filters to `status="post"` and
`kickoff < before`; walk-forward (`model_mls.py:602-619`) predicts each
fixture from `fit(prior, as_of)` with `as_of` that fixture's own kickoff
and `prior` strictly earlier. Cutoff persisted into the artifact as
`as_of` / `data_cutoff`. Textbook rolling-origin; no temporal or target
leakage found.

**Fallback classification: exemplary.** Degradations are named and
stored, not silent — `freshness_basis` (`provider` vs `capture_time`,
`models.py:392-397`), `execution_class` (`bounded_depth` vs
`top_of_book_estimate`, `models.py:597`), `top_quote_fallback`
(`paper.py:184`), explicit degraded marking at `models.py:491`.

> Note: A1 is a genuine exception to this otherwise consistent
> discipline — identity is the one place a fallback attaches silently.

**Time zones: correct.** `src/mls.py:671-679` uses
`ZoneInfo("America/New_York")` with a comment explicitly rejecting a
fixed UTC-4 offset. Everything else is UTC normalisation.

**Corpus parameter provenance: correct.** `corpus.py:64-70` publishes
`mls_goal_dispersion_cv` and `wc26_goal_dispersion_cv` under distinct
names; the model uses the MLS value (`model_mls.py:354,533`).

**Archive constants: correctly scoped.** 16-result / 84-position /
6-bundle constants appear only in archive-plane code and the readiness
endpoint's expectations.
