## 2. Findings

### A1 — Ambiguous club resolution can silently pick the wrong team

**Severity:** MEDIUM · **Class:** `ACTIVE_TRIVELA_ASSUMPTION`
**File:** `src/live/identity.py:184-189`

```python
if name:
    for t in s.query(Team).filter_by(competition_slug="mls-2026"):
        cn = norm(t.canonical_name)
        if norm(name) == cn or norm(name) in cn or cn in norm(name):
            return t
```

The name-containment fallback returns the **first** match and performs no
ambiguity check. `AGENTS.md` §6 requires the opposite: *"An ambiguous
identity match must fail explicitly, never silently pick a team."*

**Why it matters despite being dormant.** The primary path
(`abbrev == code`) is a verified 1:1 — 30/30 Sportec codes matched ESPN
abbrevs with 0 unmatched both ways on 2026-07-24, so this branch does not
run today. But the code comment states its purpose is *"defence against
future expansion drift"* — it is designed to activate precisely when the
club set changes, which is exactly when name collisions become likely.

**Concrete failure.** MLS first teams have MLS NEXT Pro reserve sides
whose names are supersets of the parent club: *Columbus Crew 2*,
*Austin FC II*, *Inter Miami CF II*, *St. Louis City SC2*. The
`cn in norm(name)` arm resolves any of these to the **first team**. The
consequence is not a crash but silent contamination: reserve-team match
stats folded into first-team xG ratings, which then feed the shadow model
and every downstream lock.

**Recommended correction.** Collect all containment matches; return only
on exactly one. On 0 or >1, return `None` and log the ambiguity so it
surfaces as missing evidence rather than a confident wrong answer —
consistent with §6's "never silently convert missing evidence into
confidence."

**Minimum acceptance test.** Seed two teams whose canonical names are in
a superset relation, resolve by the longer name with a non-matching
`code`, assert `None` rather than a `Team`. Confirm the test fails
against the current implementation.

### A2 — Live MLS alerts are branded "WC26"

**Severity:** LOW-MEDIUM · **Class:** `STALE_PATH_OR_NAME`
**File:** `src/alerts.py:55, 72`

```python
def send_ntfy(message: str, title: str = "WC26", priority: str = "high")
def send_alert(message: str, title: str = "WC26", ...)
```

This is **active operator tooling**, not documentation. `src/live/runs.py`
calls `send_alert` for live-plane events, so an operational alert about
the MLS shadow plane arrives titled "WC26". During an incident, the title
is the first thing read and it names the wrong system — the archived one.

Low blast radius, but it degrades exactly the channel that exists to
reduce confusion under pressure. The default should name the platform, or
the caller should pass a plane-specific title.

## 3. Verified sound — do not re-report

These were checked and found correct. Listed so a reviewer does not spend
its budget re-deriving them.

**Temporal leakage: clean.** `model_mls.fit(fixtures, as_of)` takes an
explicit cutoff. `_completed(s, before)` filters to `status="post"` and
`kickoff < before`. Walk-forward validation
(`model_mls.py:602-619`) predicts each fixture from `fit(prior, as_of)`
where `as_of` is that fixture's own kickoff and `prior` is strictly
earlier completed matches. The cutoff is persisted into the model
artifact as `as_of` / `data_cutoff`. This is textbook rolling-origin; no
target or temporal leakage found.

**Fallback classification: exemplary.** Every degradation path is named
and stored, not silent — `freshness_basis` (`provider` vs `capture_time`,
`models.py:392-397`), `execution_class` (`bounded_depth` vs
`top_of_book_estimate`, `models.py:597`), `top_quote_fallback`
(`paper.py:184`), and explicit "degraded" marking at `models.py:491`.
This directly satisfies §6.

**Time zones: correct.** `src/mls.py:671-679` uses
`ZoneInfo("America/New_York")` with a comment explicitly rejecting a
fixed UTC-4 offset. Everything else is UTC normalisation
(`replace(tzinfo=timezone.utc)`), which is appropriate. No fixed offsets
found in active paths.

**Competition shape: properly abstracted.** `Competition` carries
`has_group_stage` / `has_knockout_stage` booleans
(`src/live/models.py:45-46`), and MLS is seeded
`has_group_stage=False, has_knockout_stage=True`
(`src/live/db.py:115-116`) — correct, since MLS Cup playoffs are a
knockout phase. Tournament structure is data, not hardcoded control flow.

**Corpus parameter provenance: correct.** `corpus.py:64-70` publishes
both `mls_goal_dispersion_cv` and `wc26_goal_dispersion_cv` under
distinct names. The model uses the MLS value
(`model_mls.py:354, 532`). The `wc26_` prefix is accurate rather than
stale.

**Archive constants: correctly scoped.** The 16-result / 84-position /
6-bundle constants appear only in archive-plane code and the readiness
endpoint's expectations (`src/bots.py:564`, `api/main.py:607`), not in
league flows.
