# These files are closed to anything that is not a modelling change

**Four modules are hashed into the MLS engine signature:**

```text
src/live/model_mls.py       src/models/simulator.py
src/models/xg_model.py      src/models/features.py
```

`engine_signature()` sha256s their **raw bytes**. Not their logic —
their bytes. So *any* edit moves the hash:

- a helper function
- a docstring
- a type hint
- **a comment** — measured, not assumed: prepending one comment line to
  `xg_model.py` moved the signature from `b054833…` to `ff76bc8…`

## What a moved hash costs

An approval decision stores the engine hash it was made under. Boot
re-arms the plane only when that stored hash reproduces under the
**current** revision or under the revision **the decision recorded**. A
changed source fails **both** arms — correctly, because from the
guard's side an added comment and a changed simulator are the same
observation.

So the plane goes **dark**, and stays dark until an operator calls
`POST /api/admin/mls/approval/activate`. Shadow evidence collection
stops in the meantime.

**The guard is right to be this blunt.** It observes bytes; it does not
observe intent, and a signature that exempted "small" edits would exempt
whatever each author considered small. See AGENTS.md §4.

## What to do instead

Put it in a sibling module and pin the two equal by test.
`src/live/revision.py` is a worked example: the accessor it holds
belonged, by every other consideration, in `model_mls.py` beside the
constant it mirrors. It lives apart *only* because of this rule, and a
test asserts it returns the same value as
`engine_signature()["code_revision"]` — so duplication cannot drift.

`tests/test_team_style.py::test_engine_signature_modules_are_byte_identical_to_base`
fails loudly if you forget. **Its literals are a guard, not a snapshot:
if it goes red, find out why. Never paste in the new hash.**

## When you *do* mean it

A real modelling change *should* move the hash — that is the mechanism
working. Sequence it deliberately: land it between slates, have the
operator reactivate approval, and measure. Do not let it ride along with
unrelated work, because then the reactivation is paying for a change
nobody evaluated.
